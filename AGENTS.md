# AGENTS.md

This file provides guidance to agents when working with code in this repository.

- This repo is an Autotools/C++17 build, not CMake: bootstrap with `./autogen.sh`, configure from the repo root, then build with `make` ([`autogen.sh`](autogen.sh), [`configure.ac`](configure.ac), [`Makefile.am`](Makefile.am)).
- Windows has a separate native build flow under [`build_msvc/README.md`](build_msvc/README.md) using [`build_msvc/msvc-autogen.py`](build_msvc/msvc-autogen.py) before `msbuild`; don’t mix that with Autotools outputs.
- The shipped binary names are SpaceXpanse-specific: [`spacexpansed`](src/Makefile.am), [`spacexpanse-cli`](src/Makefile.am), [`spacexpanse-tx`](src/Makefile.am), [`spacexpanse-wallet`](src/Makefile.am), [`spacexpanse-util`](src/Makefile.am), [`spacexpanse-qt`](configure.ac).
- Unit-test entrypoint is [`test/test_spacexpanse`](src/Makefile.test.include), built by `make check` or targeted via `make spacexpanse_test`; a single C++ suite runs through the per-file target pattern in [`src/Makefile.test.include`](src/Makefile.test.include).
- Single C++ test file flow is non-obvious: run `make src/test/foo_tests.cpp.test` from the repo root; the rule extracts the Boost suite name from the file and writes a per-file log next to it ([`src/Makefile.test.include`](src/Makefile.test.include)).
- Functional tests are Python entrypoints under [`test/functional/`](test/functional); run one directly or through [`test/functional/test_runner.py`](test/functional/test_runner.py) with exact filenames, not bare wildcards from root ([`test/README.md`](test/README.md)).
- Functional test logs live under the temporary test datadir, with framework logs in `test_framework.log` and node logs in `node*/regtest/debug.log` ([`test/README.md`](test/README.md)).
- Python compatibility is pinned old: prefer Python 3.6 syntax/types because the repo advertises [`3.6.12`](.python-version) and linting checks for unsupported newer syntax ([`.python-version`](.python-version), [`test/functional/README.md`](test/functional/README.md)).
- C++ style follows [`src/.clang-format`](src/.clang-format) plus stricter naming rules from [`doc/developer-notes.md`](doc/developer-notes.md): snake_case variables/namespaces, `m_` members, `g_` globals, UPPER_SNAKE_CASE constants, PascalCase functions/types.
- In [`src/interfaces/`](src/interfaces), method names intentionally switch to lowerCamelCase while standalone function names remain UpperCamelCase; preserve that exception instead of normal project naming ([`doc/developer-notes.md`](doc/developer-notes.md)).
- Prefer angle-bracket project includes like `#include <wallet/wallet.h>` over quoted relative includes; this is a documented repo convention, not a compiler requirement ([`doc/developer-notes.md`](doc/developer-notes.md)).
- Internal invariant helpers from [`src/util/check.h`](src/util/check.h) are only for logic bugs: use `Assert`/`Assume`/`CHECK_NONFATAL` for internal assumptions, never for user or network input validation ([`doc/developer-notes.md`](doc/developer-notes.md)).
- New externally visible features should land in RPC first; GUI-only additions are discouraged because the GUI test surface is intentionally limited ([`doc/developer-notes.md`](doc/developer-notes.md)).
- Wallet-related changes must still compile with `--disable-wallet`; guard Berkeley DB usage behind `ENABLE_WALLET` and avoid unconditional wallet includes in shared code ([`configure.ac`](configure.ac), [`doc/developer-notes.md`](doc/developer-notes.md)).
- This repo carries upstream-style subtrees in [`src/secp256k1`](src/secp256k1), [`src/leveldb`](src/leveldb), [`src/univalue`](src/univalue), [`src/crc32c`](src/crc32c), [`src/crypto/ctaes`](src/crypto/ctaes); avoid casual in-tree edits without considering upstream sync rules ([`doc/developer-notes.md`](doc/developer-notes.md)).
- Lint is shell-script based, not a single meta tool: run individual scripts from [`test/lint/`](test/lint) or aggregate via [`test/lint/lint-all.sh`](test/lint/lint-all.sh); Python lint also runs `mypy` on functional tests and `contrib/devtools` only ([`test/README.md`](test/README.md), [`test/lint/lint-python.sh`](test/lint/lint-python.sh)).
- CI local reproduction is Docker-oriented and can mutate caches/home-mounted files; prefer targeted local test commands unless you specifically need [`./ci/test_run_all.sh`](ci/test_run_all.sh) or [`./ci/lint_run_all.sh`](ci/lint_run_all.sh) behavior ([`ci/README.md`](ci/README.md)).
